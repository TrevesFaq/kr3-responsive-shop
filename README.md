# Контрольная работа №3 — kr3-responsive-shop

Тема: «Адаптивная вёрстка и доступность многостраничного HTML/CSS-сайта».

Адаптивная версия учебного интернет-магазина из КР №1, без Bootstrap и других CSS-фреймворков. Практическая работа №12 посвящена адаптивности; аудит доступности относится к следующей практике.

Автор: Ермаченко Александр Артемович, группа ЭФБО-04-25.

## Запуск

Откройте `index.html` в браузере или запустите из корня проекта:

```bash
python -m http.server 8000
```

Адрес: http://localhost:8000.

## Практическая работа №12

- Основа перенесена из HTML/CSS-проекта КР №1 в отдельный репозиторий `kr3-responsive-shop`.
- Работа выполняется в ветке `feature/responsive-layout`.
- На всех пяти страницах проверен `viewport`, после `style.css` подключён `css/responsive.css`.
- Используется Mobile First: базовая мобильная раскладка и медиазапросы `min-width`.
- На телефоне навигация вертикальная, с 768px — горизонтальная с переносами; с 1024px логотип и меню располагаются в строку.
- Hero и страница товара имеют одну колонку на телефоне и две на широком экране.
- Карточки и отзывы: одна колонка, с 768px — две, с 1024px — три. В каталоге с 1024px появляется фильтр шириной 260px и две колонки товаров; с 1200px — три колонки товаров.
- Фильтр располагается перед товарами на телефоне, сбоку со sticky-позиционированием на desktop.
- Изображения ограничены шириной контейнера. У карточек есть `srcset`, `sizes`, размеры и `loading="lazy"`; `sizes` учитывает реальную сетку и максимальную ширину контейнера.
- Для hero используется `picture`: мобильный, планшетный и desktop-варианты. JPG-файлы локальные и имеют разные физические размеры.
- Форма: одна колонка на телефоне, две с 768px, комментарий, согласие и действия занимают всю строку. Поля и кнопки имеют высоту минимум 44px.
- Таблица сохраняет семантику и минимальную ширину 640px; горизонтальная прокрутка ограничена фокусируемым контейнером `.table-wrapper`.
- Модальное окно ограничено шириной и высотой экрана, длинное содержимое прокручивается.
- Кнопка «Наверх» на телефоне находится в потоке, чтобы не перекрывать форму; с 768px фиксируется справа внизу.
- Обработчик формы работает как в модальном окне, так и на странице заявки. Проект без backend: сообщение сообщает об успешной проверке, данные на сервер не отправляются.

## Проверка

Автоматизированная проверка выполняется в установленном Microsoft Edge через Playwright: все пять страниц на ширинах **360, 430, 768, 1024 и 1440px** (25 сочетаний).

Проверяются отсутствие горизонтального переполнения страницы и битых изображений, загрузка hero, открытие и закрытие модального окна, передача выбранного товара, размеры окна, отклонение пустой формы и успешная проверка заполненной формы. На телефоне таблица прокручивается внутри своего контейнера. Результаты и скриншоты главной сохраняются локально в игнорируемой папке `.qa/`.

Для демонстрации преподавателю откройте DevTools → режим устройства и повторите проверку всех пяти ширин. Во вкладке Network включите фильтр Img и отключите кеш, затем перезагружайте страницу при смене ширины: `picture` должен выбирать `hero-mobile.jpg`, `hero-tablet.jpg` или `hero-desktop.jpg`. Для `srcset` выбор также зависит от плотности пикселей устройства и кеша браузера. Изображения ниже первого экрана используют отложенную загрузку.

## Репозиторий и Pull Request

Репозиторий: https://github.com/TrevesFaq/kr3-responsive-shop

Ветка: `feature/responsive-layout` → `main`. Заголовок PR: `Add responsive layout styles`.

Проверка PR: открыть пять страниц на указанных ширинах, проверить меню, hero, сетки, фильтр, форму, таблицу и модальное окно; во вкладке Network проверить выбор изображений. После проверки изменений выполнить слияние PR.
